# UDP 遥测特征留样诊断台

遥测解码偶发异常时，值班员在诊断网页登记**报文特征**（十六进制载荷前缀 +
前后包数），服务对实收包自动留样：首个匹配包触发，样本包含命中包及其紧邻
的前后包，收齐后可下载 JSON Lines 核对原始载荷。

## 工作方式

- 联调程序向**独立的本机 UDP 端口**（默认 `9999/udp`）发包；服务给每个实收包
  编号（从 1 起，按到达顺序），滚动窗口只保留**最近 128 包**，照常覆盖。
- 网页登记规则：`前缀(hex) + 前包数 before + 后包数 after`。
  **登记后的首个匹配包**触发留样（每条规则只触发一次）；同包命中多条规则时
  **按登记顺序受理**。
- 触发时为完整区间 `[命中-before, 命中+after]` **预留名额**（区间里还没到的
  包也立即占额）：
  - **前段不足**（需要的更早包已滚出窗口或尚不存在）→ 本次触发报失败；
  - **名额超额**（全部样本合计预留编号 > 128，含还没到的包）→ 本次触发报失败；
  - 重叠编号只占一个名额、共用一份载荷（按编号存一份，引用计数）。
- 触发后 **5 秒**没收齐 → 样本作废；网页也可**丢弃**指定样本。作废/丢弃都
  **只归还该样本独占的名额**（仍被其他样本占用的编号保留）。
- 接收窗口照常覆盖，**收齐的样本仍可下载**：按收包顺序（编号升序）输出
  JSON Lines，每行含 `seq`（编号）、`src`（源地址）、`payload_b64`
  （Base64 载荷）。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
# 网页: http://localhost:8080
# 联调程序向本机 9999/udp 发包即可被编号留样
```

### 本地直接跑（需 Python 3.10+ 与 Flask）

```bash
pip install -r app/requirements.txt
python app/app.py        # 网页 http://localhost:8080，UDP 监听 9999
```

环境变量：`UDP_HOST`（默认 `0.0.0.0`）、`UDP_PORT`（默认 `9999`）、
`HTTP_PORT`（默认 `8080`）。

## 网页演示

1. 点「填入演示规则」再点「登记规则」：登记前缀 `deadbeef`、前 2 后 2；
2. 点「发送演示包」：服务在本机发出 40 个 UDP 包（普通遥测帧中夹两帧
   `DEADBEEF` 开头的"异常"帧）；
3. 首个异常帧触发留样，样本列表出现 5 包样本（命中包居中），
   收齐后点「下载 JSONL」即可拿到含编号/源地址/Base64 载荷的文件。

网页每秒自动刷新：运行状态（监听地址、实收总数、窗口范围、名额用量）、
规则列表、样本列表（含倒计时与失败原因）、最近实收包。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 诊断网页 |
| GET | `/api/status` | 监听地址、实收总数、窗口范围、名额用量、规则/样本统计 |
| GET | `/api/packets?limit=N` | 滚动窗口最近 N 包（编号/源地址/长度/hex 预览） |
| POST | `/api/rules` | 登记规则 `{prefix_hex, before, after}`，参数非法返回 400 |
| GET | `/api/rules` | 规则列表（含状态与失败原因） |
| DELETE | `/api/rules/<id>` | 撤销尚未触发的规则 |
| GET | `/api/samples` | 样本列表（区间、进度、状态、剩余收齐时间） |
| DELETE | `/api/samples/<id>` | 丢弃指定样本（仅归还其独占名额） |
| GET | `/api/samples/<id>/download` | 下载收齐样本的 JSON Lines |
| POST | `/api/demo` | 本机发包演示 `{count, interval_ms}` |

样本状态：`COLLECTING`（收集中）→ `COMPLETE`（已收齐，可下载）；
`EXPIRED`（5 秒未收齐作废）、`DISCARDED`（网页丢弃）、`FAILED`
（触发即失败：前段不足/名额超额，未占名额）。

## 关键实现

- `app/sampler.py`：`SamplerEngine` 单锁保护全部状态（接收线程 / 超时清扫
  线程 / HTTP 线程并发安全）。名额账本 = `编号 -> 占用样本集` 的引用计数，
  载荷按编号只存一份，多样本重叠编号天然共用；释放时仅移除本样本引用，
  引用清空才真正归还名额。
- 前段不足判定：命中包即窗口最新包，窗口存最近 128 包且 before ≤ 127，
  故仅当"命中编号 - before < 窗口最旧编号"（流初期历史不足）时失败。
- 收齐时限由独立清扫线程（0.2 s 周期）执行，查询路径也做惰性到期检查，
  保证接口看到的状态总是已结算的。
- 测试注入假时钟（`now_fn`）精确覆盖 5 秒作废与名额归还行为。

本机实测（Python 3.11 + Flask 3.1.3，直接运行 `app.py`）：

- 一条规则 after=127 占满 128 名额后，另一条命中新区间：报「名额超额」失败；
- 130 包零间隔突发全部实收编号，无遗漏。

## 限制与说明

- 诊断工具面向值班场景：Flask 内置服务器、无鉴权，请勿暴露到不可信网络。
- 样本/规则记录保存在内存，服务重启即清空；收齐样本的名额一直保留到
  被丢弃（网页会显示名额用量，值班员丢弃旧样本释放名额）。
- 作废样本的未收齐部分不保留、不可下载；需要完整区间请保证发包持续
  5 秒收齐窗口足够。
